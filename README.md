# todoist-notion-sync

A production-ready one-way sync from Todoist to Notion.

Todoist stays the source of truth for task execution. Notion becomes the searchable archive, reporting layer, and long-term history. The app never writes back to Todoist.

## Features

- Syncs Todoist `Work` and `Personal` projects into separate Notion databases.
- Creates one Notion database row per top-level Todoist task.
- Renders subtasks recursively inside the parent task page using collapsible Notion toggles.
- Keeps subtask comments and image attachments inside the matching subtask toggle.
- Syncs task comments with clean local timestamps.
- Uploads image comment attachments into Notion so they render inside the page.
- Keeps non-image attachments, such as PDFs and spreadsheets, as clickable file links.
- Marks completed Todoist tasks as `Completed` in Notion with completion timestamps.
- Marks deleted Todoist tasks as `Deleted` in Notion instead of deleting archive rows.
- Uses Todoist Sync API state plus `Sync Hash` to skip unchanged Notion pages.
- Handles retries, exponential backoff, rate limits, and structured logging.
- Runs automatically on GitHub Actions every 30 minutes.

## Architecture

```text
Todoist Sync API
        |
        v
Sync state snapshot stored in Notion
        |
        v
Change detection with Sync Hash
        |
        v
Notion task databases
```

The sync is intentionally one-way:

```text
Todoist -> Notion
```

Never:

```text
Notion -> Todoist
```

## What Gets Synced

| Todoist | Notion |
| --- | --- |
| Top-level task | Database row |
| Task title | `Task` title property |
| Task ID | `Todoist ID` text property |
| Labels | `Labels` multi-select |
| Priority | `Priority` select |
| Due date | `Due Date` date property |
| Description | Page body and `Description` property |
| Completion | `Status = Completed`, `Completed Date` |
| Deleted task | `Status = Deleted` |
| Comments | Page body under `Comments` or the matching subtask toggle |
| Image attachments | Uploaded to Notion and rendered below the comment |
| Non-image attachments | Clickable file link below the comment |
| Subtasks | Recursive Notion toggles inside the parent task page |

Only top-level Todoist tasks become Notion database rows. Subtasks do not become rows.

## Page Layout

Each Notion task page is generated by the sync and rebuilt when Todoist data changes.

```text
Description

Comments

Subtasks
  ▸ ☐ Example subtask
      Comment · 23 Jun 2026, 12:46 pm
      Comment text
      [image]
```

Do not manually edit generated page sections if you expect those edits to remain. The next sync may replace them.

## Todoist Setup

Create or use these Todoist projects with exact names:

```text
Work
Personal
```

The names are case-sensitive in the current project mapping.

Get your Todoist API token:

```text
Todoist -> Settings -> Integrations -> Developer -> API token
```

Do not commit this token to the repository.

## Notion Setup

### 1. Create a Notion integration

Create an internal integration in Notion and copy its secret.

The secret is used as:

```text
NOTION_API_TOKEN
```

Share every database below with this integration.

### 2. Create the Work and Personal task databases

Create two Notion databases:

```text
Work Tasks
Personal Tasks
```

Each database must have these exact properties:

| Property | Type | Notes |
| --- | --- | --- |
| Task | Title | Rename the default `Name` title column to `Task`. |
| Todoist ID | Text | Used for idempotency. |
| Status | Select | `Active`, `Completed`, `Deleted` |
| Labels | Multi-select | Options are created automatically by Notion. |
| Priority | Select | `Critical`, `High`, `Medium`, `Low` |
| Due Date | Date | Todoist due date. |
| Created Date | Date | Todoist created timestamp, when available. |
| Completed Date | Date | Todoist completion timestamp. |
| Last Updated | Date | Todoist update timestamp, when available. |
| Last Synced | Date | Time this app last processed the task. |
| Description | Text | Plain text copy of Todoist description. |
| Source | Select | `Todoist` |
| Sync Hash | Text | Used to skip unchanged pages. |

Copy both database IDs from their Notion URLs.

### 3. Create the Sync State database

Create one more Notion database:

```text
Todoist Sync State
```

It needs only these properties:

| Property | Type | Notes |
| --- | --- | --- |
| Key | Title | Rename the default `Name` title column to `Key`. |
| Updated At | Date | Updated by the app. |

Share this database with the same Notion integration.

The app stores Todoist's `sync_token` and local Todoist snapshot in this database. Do not edit or delete its generated row.

## Environment Variables

Create these as GitHub repository secrets, or put them in a local `.env` file for local runs.

| Variable | Required | Description |
| --- | --- | --- |
| `TODOIST_API_TOKEN` | Yes | Todoist API token. |
| `NOTION_API_TOKEN` | Yes | Notion integration secret. |
| `WORK_DATABASE_ID` | Yes | Notion database ID for Work tasks. |
| `PERSONAL_DATABASE_ID` | Yes | Notion database ID for Personal tasks. |
| `SYNC_STATE_DATABASE_ID` | Recommended | Notion database ID for Todoist sync state. Enables Todoist Sync API incremental mode. |
| `LOG_LEVEL` | No | Pino log level. Default: `info`. |
| `COMPLETED_LOOKBACK_DAYS` | No | Legacy REST fallback lookback. Default: `90`. |
| `DISPLAY_TIME_ZONE` | No | Time zone for comment timestamps. Default: `Asia/Kolkata`. |
| `MAX_IMAGE_UPLOAD_BYTES` | No | Max image upload size. Default: `5242880` bytes. |

Example `.env`:

```bash
TODOIST_API_TOKEN=
NOTION_API_TOKEN=
WORK_DATABASE_ID=
PERSONAL_DATABASE_ID=
SYNC_STATE_DATABASE_ID=
LOG_LEVEL=info
COMPLETED_LOOKBACK_DAYS=90
DISPLAY_TIME_ZONE=Asia/Kolkata
MAX_IMAGE_UPLOAD_BYTES=5242880
```

## GitHub Actions Deployment

This is the recommended deployment path.

### 1. Add repository secrets

In GitHub:

```text
Repository -> Settings -> Secrets and variables -> Actions -> New repository secret
```

Add:

```text
TODOIST_API_TOKEN
NOTION_API_TOKEN
WORK_DATABASE_ID
PERSONAL_DATABASE_ID
SYNC_STATE_DATABASE_ID
```

Paste only the secret value. Do not include quotes or `KEY=`.

### 2. Confirm workflow file

The workflow is at:

```text
.github/workflows/sync.yml
```

It runs every 30 minutes:

```yaml
on:
  schedule:
    - cron: "*/30 * * * *"
  workflow_dispatch:
```

GitHub cron uses UTC and is best-effort. Runs may start late during busy periods.

### 3. Run manually once

Go to:

```text
Actions -> Sync Todoist to Notion -> Run workflow
```

A successful manual run confirms secrets, Notion sharing, and schema setup.

### 4. Check scheduled runs

Scheduled runs appear in GitHub Actions with event:

```text
Scheduled
```

Manual test runs appear as:

```text
Manually run
```

## Sync Behavior

### Creates

If a Todoist top-level task does not exist in Notion, the app creates a new Notion page.

### Updates

If a Todoist task already exists, the app updates database properties and regenerates the page body only when the `Sync Hash` changes.

### Completes

Completed Todoist tasks are marked:

```text
Status = Completed
Completed Date = Todoist completion timestamp
```

### Deletes

Deleted Todoist tasks are not deleted from Notion.

They are marked:

```text
Status = Deleted
```

### Subtasks

Subtasks are rendered recursively as Notion toggles inside the parent task page. They do not become database rows.

### Comments and Attachments

Top-level task comments appear under `Comments`.

Subtask comments appear inside the matching subtask toggle.

Image attachments are uploaded into Notion and rendered below the related comment.

Non-image attachments are shown as clickable file names below the related comment.

## Priority Mapping

| Todoist | Notion |
| --- | --- |
| P1 | Critical |
| P2 | High |
| P3 | Medium |
| P4 or unset | Low |

Low priority is hidden in the subtask toggle title to reduce visual noise.

## Efficiency

The app uses two layers of efficiency:

1. Todoist Sync API state stored in Notion via `SYNC_STATE_DATABASE_ID`.
2. Per-task `Sync Hash` stored in each task database row.

This means unchanged tasks are skipped. Their Notion pages are not rewritten, and unchanged images are not re-uploaded.

If `SYNC_STATE_DATABASE_ID` is missing, the app falls back to the older REST-based sync mode.

## Troubleshooting

### `Could not find database with ID`

The Notion database is not shared with your integration, or the wrong database ID is configured.

Fix:

- Open the database in Notion.
- Click `Share`.
- Invite the Notion integration.
- Confirm the GitHub secret has the correct database ID.

### `Task is not a property that exists`

The title property in the Notion database is not named `Task`.

Fix:

- Rename the default title column, often called `Name`, to `Task`.

### `Request failed with status code 401`

Usually the Todoist token is wrong, revoked, missing, or pasted with extra characters.

Fix:

- Regenerate or recopy the Todoist API token.
- Update the `TODOIST_API_TOKEN` GitHub secret.

### Workflow says dependency lock file is missing

This happens when `actions/setup-node` uses `cache: npm` without a lockfile.

Fix:

- Remove `cache: npm` from `.github/workflows/sync.yml`, or commit a `package-lock.json` and switch to `npm ci`.

### Scheduled workflow does not run exactly at `:00` or `:30`

This is normal. GitHub scheduled workflows are best-effort and may be delayed.

### Image does not appear in Notion

Check:

- The image is attached to a Todoist comment, not just visible elsewhere.
- The task or subtask containing the comment is in the synced project.
- The image is below `MAX_IMAGE_UPLOAD_BYTES`.
- The GitHub Action log does not show an image upload warning.

### Subtask comment image does not appear

Subtask comments are rendered inside the matching subtask toggle. Expand the toggle in Notion.

## Security Notes

- Never commit `.env`.
- Never paste API tokens in issues, screenshots, README files, or chat logs.
- If a token is exposed, rotate it immediately.
- Use GitHub repository secrets for deployment.
- The sync is one-way and never writes to Todoist.

## Known Limitations

- GitHub scheduled workflows are not exact timers.
- Notion direct file uploads have workspace and file-size limits.
- Multi-part Notion file upload for very large files is intentionally not implemented.
- Generated page sections are replaced when Todoist data changes.
- Current project mapping expects Todoist projects named exactly `Work` and `Personal`.
